Auth ปิดไว้เป็นค่าตั้งต้น

ถ้าไม่มี CRON_SECRET จะตอบ 503 ไม่เปิดให้เรียกได้ฟรี pg_cron อ่าน secret จาก Supabase Vault ตอนยิง request

ไม่มี public API

ทั้ง 4 route เป็น POST และมี cron เป็นผู้เรียกเท่านั้น หน้าเว็บไม่เรียก API ใดเลย แต่อ่าน Supabase ผ่าน queries.ts

Idempotent

daily-summary และ story ข้ามหุ้นที่ทำเสร็จแล้ว การยิง tick ซ้ำจึงเป็น retry ไม่ใช่การเสียโควตาซ้ำ

responses

Response bodies

ทุก route ใช้ status เหมือนกัน: 503 ถ้าไม่ได้ตั้ง CRON_SECRET, 401 ถ้า bearer ไม่ตรง, 502 { error } ถ้า job throw

Endpoint200 response body
/api/refresh{ symbols, prices, snapshots, failed[], timelines, timelineFailed[] } หรือ { skipped: "market closed" }
/api/ingest-news{ fetched, alreadyStored, stored, summarised, awaitingSummary, aiCalls, tokens, failed[] }
/api/daily-summary{ tradingDay, alreadyDone, generated[], timelines[], timelinesSkipped[], preambleMs, stale[], geminiCalls, calls[], failed[] } หรือ { skipped: "market still open" }
/api/story{ tradingDay, alreadyDone, generated[], stale[], skippedRateLimited[], failed[], marketStory } โดย marketStory.status เป็น deferred, already_done, generated, rate_limited หรือ failed
