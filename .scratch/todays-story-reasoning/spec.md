# Today's Story: give it real reasoning, not just restatement

> **Superseded in one place**: a follow-up ticket, `.scratch/todays-story-guideline/spec.md`, moves the reasoning-instruction text (anti-redundancy, cross-referencing guidance, and new analyst-derived reasoning principles) into its own importable module rather than inline in `buildPrompt`. Everything else below is unchanged and still applies — implement both together, or this one first and the guideline ticket second.

## Problem Statement

Today's Story's AI narrative reads as a restatement of numbers the page's stat cards already show, not as analysis. A visitor gets 8 labeled paragraphs that mostly translate a pre-computed label into a sentence ("today's move is company-specific") rather than reasoning about what several data points together imply. The richest input the recent build added — company fundamentals (EPS/revenue growth, earnings surprise) — is never connected to the day's price action at all, because the rule permitting inference was scoped to only 2 of the 8 sections, and even those two are capped at 1-3 sentences, leaving no room for a real argument. Separately, while investigating why fundamentals-based reasoning would have nothing to work with, the `fundamentals` table was found to be completely empty in production, for a bug reason unrelated to data availability.

## Solution

Loosen the prompt's causal-inference rule from 2 of 8 sections to all 8, so every section may reason across the full input rather than restating only its own named slice; remove the blanket sentence-count cap so reasoning has room to appear; add an explicit anti-redundancy instruction so the now-unconstrained sections don't converge on repeating each other; widen the existing `headline` section's scope into a short "What Happened" overview (price + top news in brief) so it reads as a deliberate summary lede, distinct from the 7 sections of deep analysis beneath it; wire the already-generated news summary paraphrase into the prompt in place of bare headlines, so news-driven reasoning has real article content to work from instead of a title; turn on Groq's reasoning effort and set an explicit completion-token ceiling now that the model is expected to actually think before answering; and fix the root cause of the empty `fundamentals` table (a one-time backfill script decoupled from the market-hours-gated cron, with the existing staleness re-fetch kept as a passive, zero-extra-cost safety net).

## User Stories

1. As a visitor reading Today's Story, I want the "Business & Fundamentals" section to say whether today's price/peer performance is consistent or inconsistent with the company's earnings/growth trend, so I learn something the stat cards don't already tell me.
2. As a visitor, I want the "Company-Specific or Market-Wide", "Unusual vs. History", "Sector, Market & Peers", and "Year-to-Date" sections to be able to draw on any of the day's computed figures (not just their own named slice) when it strengthens the argument, so the narrative reads as one coherent analysis rather than eight independent restatements.
3. As a visitor, I want each section to avoid repeating a conclusion an earlier section already stated, so reading top-to-bottom doesn't feel like the same insight said three different ways.
4. As a visitor, I want a short "What Happened" overview at the top of the story (price move + the news that matters, in brief) clearly distinguishable from the analytical sections below it, so I can get the gist in one line before reading deeper.
5. As a visitor, I want news-grounded reasoning (in "Why It Moved" especially) to draw on the actual content of an article, not just its headline, so the connection it draws is substantive rather than guessed from a title.
6. As the project owner, I want every section to still only ever use facts present in the structured input — no invented numbers, no predictions, no investment advice — so the product stays inside its stated "what happened" scope even with the causal-inference rule loosened project-wide.
7. As the project owner, I want a single call per stock to remain the architecture (no tool-calling, no multi-turn) so the Groq TPM budget and the "one call per stock" design already locked in the project's build docs are undisturbed.
8. As the project owner, I want the `fundamentals` table to actually contain data for all 20 tracked symbols without needing to wait for the next market-hours cron tick, so this ticket's own verification isn't blocked and future demos aren't silently missing fundamentals for days after a Friday-evening deploy.
9. As the project owner, I want the fundamentals ingestion's dependency on market hours removed at its root (a one-time/occasional backfill script, decoupled from the refresh endpoint's market-hours gate) rather than patched around, so the same silent-gap failure can't recur after a future weekend deploy.
10. As the project owner, I want the existing 7-day staleness re-fetch inside the refresh job kept as-is (not removed), so fundamentals silently self-heal even if nobody remembers to rerun the backfill script by hand.
11. As the project owner, I want every rule change here recorded in the project's build docs the same way every other reversal in that file is recorded (what changed, why, what didn't change), so a future reader doesn't have to re-derive the reasoning or mistake this for an accidental drift from a documented, locked decision.
12. As the project owner, I want the on-page disclosure footer under Today's Story updated to describe the new, project-wide inference rule instead of the old 2-section carve-out, so the UI's own stated boundary stays accurate.

## Implementation Decisions

- **Prompt (`buildPrompt`)**:
  - Remove the input-shape hints that discourage synthesis (`"... (already computed, state it, do not re-derive it)"` on the movement classification, range label, earnings surprise, EPS/revenue growth trend fields) — replace with plain descriptive key labels. The values are still 100% engine-computed; only the instruction *not to reason from them* is removed. "Never calculate a new number" already prevents the model from inventing a different value for any of these.
  - Remove the rule restricting causal claims to only 2 named sections. Add a replacement guardrail: every reasoning step must point to a specific figure or label present in the input; no outside fact, cause, or event may be introduced.
  - Add an explicit anti-redundancy instruction: a section should not restate a conclusion an earlier section already reached — each takes its own angle on the same underlying data.
  - Rewrite the other analytical sections to explicitly invite cross-referencing the whole input, not just each section's previously-named slice — most concretely, the fundamentals section must now state whether the day's price/peer/sector performance is consistent or inconsistent with the fundamentals trend, which today it never does.
  - Remove the blanket "short string (1-3 sentences)" cap for the 7 analytical sections; length is however long the grounded reasoning needs. The headline section stays short (roughly a sentence or two).
  - Widen the headline section's brief from "pick the one news item that most deserves attention" to a short "What Happened" overview: today's price move plus the news pick and its reason, still brief, explicitly framed (in the prompt and in the rendered section label) as the summary lede that the 7 sections below go on to analyze. The stored shape is unchanged; only the brief and the rendered section label change.
  - Add the raw relative-volume figure to the price block of the prompt input — it's already computed during story generation but currently never passed into the prompt, so today the model only ever sees a "Significant/Normal" verdict, never the number behind it (e.g. "2.8x average"). Exposing it gives the unusualness and comparison sections something concrete to cite instead of a bare verdict.
  - Wire the existing AI-generated news paraphrase (already produced once per news article by the news-ingestion pipeline, stored alongside each article) into the "news today" block in place of the bare headline. An article with no paraphrase yet (not every article gets one immediately) falls back to headline-only, same as today.
  - Keep unchanged: never invent a fact/number/timestamp/news item, never calculate a new number, never predict future prices/trends/outcomes, never give investment advice, and every fixed fallback line used verbatim when the underlying data doesn't support a claim.

- **Groq call**: add an optional reasoning-effort parameter (default "high" for this call site), and an explicit completion-token ceiling — currently neither is set. The ceiling is the real backstop now that the prompt no longer caps sentence count; its value is set from what's actually measured in verification, not guessed in advance, and should leave a single call comfortably under half of Groq's per-minute token budget so the two calls that can land in the same scheduled tick both fit. If "high" reasoning effort pushes token usage too close to that ceiling, fall back to "medium"; record whichever is chosen and why.

- **Fundamentals bug — root cause and fix.** Queried the live `fundamentals` table directly: 0 rows for all 20 symbols. Traced, not guessed: the market-data refresh job only fetches fundamentals inline, per-symbol, inside the same cron tick that fetches price/volume, and the refresh endpoint refuses to do any work outside market hours. The fundamentals-pipeline code deployed on a Friday evening; the market has been closed (weekend) ever since, so the code has never once executed. Confirmed this is not an upstream-API problem — the two Finnhub endpoints involved both return real data live for a test symbol on the current key. Fundamentals data has no market-hours dependency at all; it was made to wait behind a gate that exists for price freshness, which has nothing to do with it.
  - Add a one-time backfill script mirroring the existing daily-closes backfill script's shape exactly (concurrency-limited, human-triggered, calls the upstream API directly rather than through the gated refresh endpoint, no scheduler secret involved): for each of the Top 20 symbols, fetch the growth/margin metrics and latest-earnings data and upsert into `fundamentals`, same shape the refresh job's own fundamentals-write block already produces.
  - Keep the refresh job's existing 7-day staleness re-fetch as-is — it costs nothing extra when data is fresh (a cheap lookup, no upstream call) and self-heals if the backfill script is never rerun by hand.
  - Run the backfill script once as part of landing this change, so fundamentals-based verification isn't blocked on the next market open.

- **UI**: relabel the headline block from an unlabeled news-pick lede to "What Happened" framing (still the unlabeled opening line stylistically — no new section-header treatment needed, just the copy/brief change flowing through from the prompt). Update the disclosure footer (currently calling out the two sections that may infer a connection, by name) to state the rule now applies project-wide, while restating what still never changes (no invented facts, no predictions, no advice).

- **Project build docs**: record this as an explicit reversal, alongside the existing note about Today's Story replacing the old AI Daily Summary — what changed (causal-inference exception widened from 2 to 8 sections; sentence cap removed), why (the richest computed input, fundamentals, was structurally never reachable by the one exception wide enough to use it), what didn't change (no new numbers, no predictions, no advice — grounding in given data is what keeps this safe, not the section-count of the exception). Update the parenthetical that currently says the loosening applies to only two sections. Record the fundamentals bug (symptom, root cause, fix) in the same voice as the file's other "found and fixed" entries. Record whichever reasoning-effort level verification settles on, and why.

## Testing Decisions

- No automated test seam is added for the prompt/reasoning changes, the fundamentals bug fix, or the backfill script — confirmed with the project owner. The narrative-generation module, the Groq HTTP client module, and the daily-closes backfill script being mirrored have no test files today, and the original Today's Story spec explicitly excused the Groq HTTP client from required test coverage.
- Verification is manual, matching the bar this project already sets for every AI-prompt change ("read it yourself, don't trust it's probably fine"): trigger the story job for a handful of stocks, read the token usage back off the call result to confirm the token ceiling is set from a real measurement, and read the generated sections against the underlying raw numbers (price cache, daily closes, fundamentals, news/news summaries) to confirm every claim traces to real input data and that fundamentals/price/peer data are now actually being reconciled rather than reported in isolation.
- Optional, not required: a test on the Groq client that mocks `fetch` and asserts the request body includes the reasoning-effort and completion-token-ceiling fields with the expected values — flagged during seam review, left for later if call-shape coverage is wanted.
- Type-check and lint clean, as usual.
- Load the Today's Activity page in a browser for at least one stock and confirm longer section text renders cleanly next to its chart at both a wide and a narrow (~600px) viewport.

## Out of Scope

- **SEC EDGAR 8-K filings as a new data source.** Verified live during planning (ticker→CIK mapping file, and a per-company structured filings endpoint including 8-K item codes) — free, no API key, real signal (material-event filings) available. Deliberately deferred to its own ticket: it needs a new client, table, ingestion step, a ticker→CIK map, noise filtering (a symbol's filing history is mostly routine insider-trading notices, which would have to be filtered out to surface only the material filings), a retention decision, and it reverses this project's explicit prior "SEC filings: never built, and not owed" decision — enough independent surface area that bundling it here would make this ticket harder to verify and roll back independently.
- **Splitting Today's Story from one panel into a card per section.** A layout/composition change — sections without a chart become plain card content, sections with one keep their two-column text+chart treatment, and the opening "What Happened" overview reads as a distinct lede card ahead of the 7 analytical cards. Deferred because it's a pure UI/composition decision, independent of the reasoning-depth work in this ticket.
- **Disabling the orphaned daily-summary Gemini cron job.** Still runs daily, still writes to its own table, nothing reads it. Confirmed with the project owner this ticket does not revive or reuse that content (it's the exact "pure restatement" content Today's Story was built to replace) and does not touch that cron schedule either — this is a known, deliberately owner-owned infra cleanup, unrelated to this ticket's scope.
- Any change to the 8-key JSON shape stored per story — this ticket changes prompt content and length, not the schema already in place.
- Backfilling/regenerating already-stored stories under the new prompt — out of scope, same as the original Today's Story spec explicitly excluded backfilling story generation for past days. New prompt behavior takes effect from the next generation run onward.

## Further Notes

- The Groq model backing this call is a reasoning model; the client today sets neither a reasoning-effort parameter nor a completion-token ceiling, so this ticket is the first time either knob is touched — treat the token measurement taken during verification as the source of truth, the same posture this project already takes toward every other AI-provider constraint ("measured live," never assumed from a blog post).
- The fundamentals bug was found by directly querying the live `fundamentals` table while checking whether there was even data to reason over for this ticket's own verification — worth keeping as a reminder that "the feature is built" and "the feature has data in production" are different claims, especially across a weekend deploy against a market-hours-gated pipeline.
- This spec is the output of an extended grilling session (Thai-language) with the project owner; the settled micro-decisions inside it — no cross-section redundancy, no backfill of past stories, JSON-truncation failures fall through to the existing failed/next-run retry path unchanged, and staleness re-fetch kept as a passive safety net alongside the new backfill script — were each explicitly confirmed, not assumed.
