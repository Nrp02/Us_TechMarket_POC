# Narrative backfill audit — 2026-09-27

Intent: explain each session by connecting stored evidence, with business results as continuing context rather than requiring new earnings every day.

Smaller alternative: retain the existing deterministic engines and production AI prompt; replay historical inputs through that narrative pipeline instead of maintaining a separate prose generator. Historical inputs need an explicit availability cutoff.

## Confirmed findings

1. **Blocker: the backfill bypasses AI entirely.** `.scratch/recent-trend/backfill-manual-analysis.mts:1` explicitly says no LLM/provider calls. `synthesizeStock` writes literal prose at lines 99–126; market prose at lines 155–174. It upserts directly into the production tables at the end. Live reads captured 100 stock rows and 5 market rows for September 21–25. Every stock fundamentals string exactly matches line 110; every explanation matches that script's template. The production prompt/guideline/reasoning effort cannot affect these rows. Change: regenerate through the real narrative pipeline after preparing historical inputs, not by templating sections.

2. **Major: business context is deliberately removed.** Backfill line 85 passes `fundamentals: null`; line 110 inserts the same implementation explanation for every session/symbol. Live fundamentals has 20 rows. The original reasoning spec user story 1 and `src/lib/story-generation.ts:325` require reconciling earnings/growth trends with today's stock/peer/sector performance. Existing classifiers compare quarterly YoY growth against TTM YoY; no daily new filing is required. However, today's 20 rows do not prove availability on earlier sessions: migration 0011 stores one overwritten cache row per symbol, with fetch time and fiscal period but no release/first-known time. NVDA's captured fiscal period is 2026-09-30, which must not be mistaken for a publication date. Change: reuse the latest fundamentals known by the analyzed session, identify its period/availability, and explain price alignment or tension without claiming old results are a fresh catalyst. Recover an as-of source for old sessions; missing history remains an explicit limitation, not permission to project current facts backwards.

3. **Major: the backfill violates the three-ticket output contract.** Stock headline line 105 repeats Recent Trend although ticket 02 and `story-generation.ts:350` scope it to unusualness only. All captured stock headlines contain this leak. Explanation lines 99–103 only quote the newest headline and disclaim causation; they never use the article summary or reconcile peers/volume/business evidence. Comparison and peer relation repeat the same peer figures; YTD is just two percentages. This is built into the templates, not evidence that the production model ignored its prompt. Change: use the actual prompt and inspect all sections against complete inputs, including news/fundamentals; the earlier smoke review explicitly omitted those inputs.

4. **Major: market backfill uses a different population.** Backfill line 132 uses only `STOCK_SYMBOLS` (Top 20); production `src/lib/market-story-generation.ts:361` uses `TRACKED_STOCK_SYMBOLS` (43 tracked stocks). Captured September 25 breadth is 10/10 of 20 and semiconductor leadership +0.65%. These are not equivalent to the production tracked-universe read. Availability must be measured before making a 43-stock historical claim. Change: use the same population/read rules as production and explicitly disclose missing historical members.

5. **Major: existing rows suppress normal regeneration.** Stock `story-generation.ts:578,584,608` treats every stored symbol/day as done. Market `market-story-generation.ts:327` returns already_done for an existing row. A successful template upsert therefore prevents the scheduled AI job from replacing it. Further, stock generation reads latest `price_cache`; blindly calling `generateOneStory` for older days can combine today's prices with historical closes/news. Change: targeted replacement through a historical-input replay; retain an export of old rows and inspect draft output before persistence. A cron retry alone will not repair these rows.
