# Today's Story — spec

## Problem Statement

Today's Activity page only ever describes a single trading session — nothing tells a visitor how a stock has done since the start of the year, the start of the month, or relative to its peers. The AI narrative on the page mostly restates numbers the stat cards already show, because the AI Safety Rules ban it from claiming causation the source articles don't state explicitly, which leaves it with little to add beyond paraphrase.

## Solution

Add a year of historical daily-close data and quarterly fundamentals data per symbol; compute a set of pure-function "engines" from that data (peer comparison, sector/market divergence, company-vs-market classification, volatility percentile, YTD/MTD return, 52-week range position, earnings surprise, fundamentals trend); feed all of it into a redesigned AI narrative ("Today's Story") that answers 8 analytical questions per stock, generated by a second AI provider (Groq) chosen for its per-minute-token free tier rather than Gemini's per-day-request tier; extend the existing stat-card row with two new cards (Peers, Period Performance); and add small data visualizations to the 3 sections of the story that carry genuinely chartable numeric data.

## User Stories

1. As a visitor, I want to see a stock's year-to-date return, so I can judge its longer-term performance beyond today's session.
2. As a visitor, I want to see a stock's month-to-date return, so I can judge its recent short-term trend.
3. As a visitor, I want to see how a stock's peers moved today, so I can tell whether today's move is company-specific or shared across similar companies.
4. As a visitor, I want a single stat card showing both YTD and MTD, so I don't have to scan two separate cards for related numbers.
5. As a visitor, I want to see whether today's move deserves attention, so I can quickly judge significance without reading the whole page.
6. As a visitor, I want to see whether a stock's move is unusual compared to its own history, so I can judge whether today is an outlier day.
7. As a visitor, I want to see whether a move is company-specific or market-wide, so I know whether to attribute it to the company or to broader conditions.
8. As a visitor, I want a plausible, data-grounded explanation of why a stock moved today, so I understand the story behind the numbers, not just the numbers themselves.
9. As a visitor, I want to see how the underlying business has been performing (earnings, revenue growth), so I can judge whether today's price move fits the company's fundamentals.
10. As a visitor, I want to see whether a stock's move relates to its peers or sector moving the same way, so I can judge how isolated or connected today's move is.
11. As a visitor, I want a narrative summary of what the YTD trend tells me, so I don't have to interpret the raw percentage myself.
12. As a visitor, I want the story to read top-to-bottom as a coherent narrative rather than a grid of disconnected cards, so the page feels like a briefing rather than a dashboard.
13. As a visitor, I want a headline that tells me which of today's news items deserves attention, with a stated reason, so I know where to look first among several articles.
14. As a visitor, I want charts next to the sections that carry genuinely numeric/comparative data, so I can see the shape of the data, not just read a sentence about it.
15. As a visitor, I do not want a chart cluttering sections that are purely narrative, so the page doesn't feel repetitive.
16. As a visitor on a phone, I want the two-column text/chart sections to stack vertically, so the page remains usable on a small screen.
17. As a visitor, I do not want the AI to predict future price movement or offer investment advice anywhere on the page, so the product stays within its stated "what happened" scope.
18. As a visitor, I do not want the AI to invent facts, numbers, or timestamps, so the narrative stays trustworthy.
19. As a visitor, I do not want the "deserving attention" headline pick to double as a price-causation claim, so it stays a distinct, checkable editorial choice rather than duplicating the causal-explanation section.
20. As the project owner, I want the page still to load correctly if any single stock's story generation fails for a day, so a Groq rate limit or an outage doesn't take down the whole page.
21. As the project owner, I want the existing stat cards, price/volume chart, and Today's Timeline to remain unchanged in presence, so this feature is additive, not a rebuild.
22. As the project owner, I want the page still reachable and correctly labeled from the nav even though its displayed name changes from "Today's Activity" to "Today's Story", so existing links/shortcuts/bookmarks don't break.
23. As the project owner, I want the AI call budget to stay within each provider's free tier, so the deployed demo never hits a paid tier or a hard quota wall during a demo.
24. As the project owner, I want historical daily-close data backfilled once for all 25 tracked symbols, so Market Overview can reuse the same table later without a second backfill.
25. As the project owner, I want the historical data retained on a rolling ~370-day window rather than growing forever, so the free-tier database doesn't fill up.
26. As the project owner, I want fundamentals data refreshed only when stale, so the ingestion job doesn't waste calls on data that only changes quarterly.
27. As the project owner, I want the causation-rule policy change recorded as an explicit, reasoned decision in the project's documentation, so future readers understand why a previously locked safety rule was loosened.

## Implementation Decisions

- New table `daily_closes` (symbol, trading_day, close, change, change_percent), PK (symbol, trading_day); retained on a rolling ~370-day guarded-delete window added to the existing prune function.
- One-time backfill script populates `daily_closes` for all 25 tracked symbols from Yahoo's unauthenticated chart endpoint (1-year range, daily interval).
- An ongoing hook inside the existing 15-minute refresh cycle writes one `daily_closes` row per symbol once the session's closing print is available, reusing the price already reconciled for `price_cache` — no new upstream call.
- New table `fundamentals` (symbol PK, EPS/revenue growth fields, margins, latest earnings period + surprise%, updated_at), excluded from retention pruning (small fixed-size cache, same treatment as the existing quote cache).
- Fundamentals populate from two Finnhub endpoints already reachable on the free tier: the metrics endpoint already called for average volume (additional fields extracted from the same response, previously discarded) and the earnings endpoint (new call). Refreshed only when the cached row is missing or older than 7 days.
- New hardcoded peer map (Top-20 symbol → 2–4 peer tickers) populated by a one-time manual lookup; not fetched live.
- New pure computation engines: peer average % change, sector/market divergence, company-specific-vs-market-wide classifier, volatility percentile (position within the symbol's own 370-day daily-move history), 52-week high/low range position, earnings-surprise classifier, fundamentals trend classifier, and a story-input assembler composing all of the above plus the day's news into one payload.
- Stat card row extends from 5 to 7 cards: "Peers" (this stock's change vs. peer average) and "Period Performance" (YTD + MTD in one card). The 5 existing cards are unchanged in content; grid breakpoints are re-derived for 7 cards rather than reused from the 5-card math.
- The page's AI narrative restructures from a 3-field schema into an 8-section ordered narrative ("Today's Story"): headline (rule-based significance badge + AI-selected news item with a stated, non-causal reason), sector/market/peer comparison, company-vs-market classification, unusualness vs. history, causal explanation, business/fundamentals, peer/sector relation, YTD takeaway.
- The narrative-generation call moves to Groq (`openai/gpt-oss-20b`) for this call only; news summarization stays on Gemini, unchanged. Batch size drops from multiple stocks per call to one stock per call — Groq's binding constraint is tokens-per-minute (measured live: 8,000 TPM against a 1,000/day rolling request budget), not requests-per-day, and a per-stock call removes the multi-stock JSON-truncation failure mode already seen twice in this codebase. 20 calls/day (one per Top-20 symbol) replace the old 4 batch calls/day, paced 2 stocks per cron tick across 10 of the existing 12 ticks.
- On a rate-limit response, the job does not retry immediately; it leaves that stock without a story for the current run and relies on the next scheduled run to pick up any stock still missing one, the same pattern `selectForSummary` already uses for news.
- One existing AI safety restriction is deliberately loosened: the narrative may infer a plausible, data-grounded connection between the day's news/peer/sector movement and the stock's price move without requiring the source article to state that link explicitly. Two other restrictions are explicitly kept: no self-calculated numbers, and no prediction/investment advice. This reverses a previously tested and locked decision (the recorded "Norway sovereign wealth fund" false-causation case) and must be recorded as such in CLAUDE.md, with the accepted tradeoff stated plainly.
- The headline section's "what deserves attention" news pick is a selection with a stated reason, not a self-graded importance score (the pattern already rejected for Confidence Score/impact-score). The reason must be grounded in the article's own content/metadata (topic, recency, company-specific vs. industry-wide), never a price-causation claim — causation stays the explanation section's job exclusively.
- Data visualization is added selectively to 3 of the 8 narrative sections (sector/market/peer comparison — short horizontal bar chart; unusual-vs-history — position marker on a min–max range bar; YTD takeaway — line/area chart of daily closes since the start of the year), with a 4th (business/fundamentals — EPS actual vs. estimate, last 4 quarters) optional and cuttable first. Sections without inherently numeric content stay text-only. Wide viewports use a two-column split (text left, chart right) for sections with a chart; narrow viewports stack.
- The page's user-facing name changes from "Today's Activity" to "Today's Story" (nav label and page heading only). URL route, internal file/component names, and the existing keyboard shortcut are unchanged. No existing page content is removed — the new narrative replaces only the current AI summary card, in place.

## Testing Decisions

- Good tests here exercise external behavior of the computation layer, not implementation details: given raw inputs (prices, peer prices, historical closes, fundamentals fields), each engine's output (a number or a fixed classification label) is asserted directly.
- Primary seam: the story-input assembler that composes every computation engine's output into the payload sent to the AI. Testing at this one seam exercises every engine it composes, rather than testing each engine file in isolation.
- Prior art in this codebase: existing pure-function rule modules with no live-database import, tested with hand-picked input scenarios including edge cases (missing baseline, empty history).
- Explicitly not covered by this seam: the database read/write layer — this repo has no isolated test database and local test runs already write to the production database (an accepted, pre-existing tradeoff), so this spec does not add new automated tests against real reads/writes.
- Also not covered: the Groq HTTP client — an optional second seam (mock the fetch boundary) if call-shape/error-handling coverage is wanted later, not required for this spec.

## Out of Scope

- A dedicated "Financials" tab or any new secondary navigation.
- Reopening the "no secondary tab bar" decision more broadly.
- True cross-company "industry impact" analysis — reframed as data-grounded peer/sector correlation instead.
- Predicting future price/trend or offering investment advice anywhere in the narrative.
- Self-calculated numbers by the AI.
- Changing the page's URL route, file/component names, or keyboard shortcut.
- Removing or restructuring any of the page's existing content.
- A second, isolated test database.
- Backfilling fundamentals or story generation retroactively for past days.

## Further Notes

- Groq's free-tier constraints were measured live during planning, not assumed: a generous rolling daily request budget (1,000/day), and a much tighter per-minute token budget (8,000 TPM) — the latter is what actually drove the batch-size-of-1 decision.
- Fundamentals data-source availability on the free tier was also verified live during planning (`/stock/metric?metric=all` and `/stock/earnings` both returned real data for AAPL on the existing Finnhub key).
- This spec reverses a previously locked, tested AI-safety decision — implementers should read the existing recorded rationale for that lock before touching the prompt, and carry the reasoning for the reversal into CLAUDE.md.
- The Groq API key is already present in `.env.local` and confirmed covered by the existing `.gitignore` `.env*` pattern; no credential-handling change is needed.
