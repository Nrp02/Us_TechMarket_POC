# 06: Data visualizations in Today's Story

**What to build:** A visitor sees small charts beside the three (optionally four) Today's Story sections whose content is genuinely numeric and comparative: a short bar chart comparing this stock's move to sector/market/peers, a range bar showing where today's move sits in the stock's own history, and a line/area chart of the YTD price trend. The remaining sections (headline, classification, causal explanation, peer/sector relation) stay text-only, so the page keeps alternating between full-width prose and two-column sections rather than turning into a uniform grid.

**Blocked by:** 05 (needs the section layout to attach charts to).

**Status:** built, with the optional 4th chart cut — `npx tsc --noEmit`, `npm run lint`, `npm test` all clean; verified against real production data for NVDA. Live-browser responsive verification not done this session (see ticket 05's note — Claude in Chrome was not connected).

- [x] The sector/market/peer comparison section shows a short horizontal bar chart (this stock, sector, market, peer average) beside its text on wide viewports. `ComparisonBars` in `src/components/story-charts.tsx`; fed `ticker.changePercent`, `sector?.changePercent`, `market?.changePercent`, `peers.peerAveragePercent` — all already on the `Activity` payload, no new query.
- [x] The unusual-vs-history section shows a min–max range bar for the stock's own historical daily moves with today's move marked on it. `RangeBar`, fed the min/max of `Activity.dailyCloses` (up to 370 days) and the current price. Read as the 52-week price range (matching the existing `rangeLabel`/`rangePosition` concept in `src/lib/volatility.ts`), not the change% volatility percentile — the spec names this visual a "min–max range bar," which is what a price range naturally is; the percentile figure stays text-only in the "unusualness" narrative itself.
- [x] The YTD takeaway section shows a line/area chart of daily closes since the start of the year, sourced from the same historical data backing the Period Performance card. `YtdChart`, filtered from `Activity.dailyCloses` to the newest stored row's year — same `daily_closes` rows `computePeriodPerformance` already runs on, no second fetch.
- [x] (Optional, cut first if needed) The business/fundamentals section shows a small bar chart of EPS actual vs. estimate for the last 4 quarters. **Cut**, per the ticket's own explicit permission to cut this one first — `fundamentals` is still an empty table in production (ticket 02's unresolved backfill), so there is no real data to chart yet, and the ticket named this chart optional specifically to be dropped under exactly that condition.
- [x] On wide viewports, each charted section splits into text (left) and chart (right); below the project's phone breakpoint, the chart stacks under the text. `StorySection` in `todays-story.tsx` uses `min-[600px]:grid-cols-[minmax(0,1fr)_200px]` — 600px matches the phone-tier breakpoint CLAUDE.md's responsive section already establishes elsewhere in this app (gutters, nav-card row-wrap). Below 600px the grid isn't applied and the two stack in source order.
- [x] Sections without a chart (headline, classification, causal explanation, peer/sector relation) remain full-width text with no empty chart placeholder. `StorySection`'s `chart` prop is optional; when omitted (or when a chart function like `rangeChart`/`ytdChart` returns `undefined` for insufficient data) the section renders as a single full-width paragraph, never a two-column grid with an empty cell.
- [x] Charts follow the project's existing visual/color conventions (reuse the sparkline component's approach where the shape fits) rather than introducing a new, inconsistent chart style. `YtdChart` reuses `Sparkline`'s exact polyline/polygon-over-gradient drawing and the document-level `session-up`/`session-down` gradient defs from `chart-gradients.tsx`. `ComparisonBars`/`RangeBar` are plain CSS bars (a single magnitude on a scale, which needs no SVG) using the same `--color-semantic-up/down`/`--color-surface-soft`/`--color-hairline` tokens as the rest of the app; `RangeBar`'s "today" marker uses `--color-primary`, matching the Signal Blue rule's existing use for timeline price-milestone markers (DESIGN.md) rather than introducing a new decorative use of the accent.
- [ ] Checked at the project's standard test widths with no horizontal overflow introduced by the new charts. **Not verified live this session** — see ticket 05's identical note. Both new chart components are narrower than existing charts that are already known to fit (`YtdChart`'s `w-full h-auto` viewBox scaling matches `Sparkline`; `ComparisonBars`/`RangeBar` are flex/CSS, not fixed-width), so overflow is unlikely, but this should be confirmed in a browser rather than assumed.
